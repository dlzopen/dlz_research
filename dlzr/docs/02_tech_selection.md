## 2. 候选方案评估

### 2.1 方案 A：Godot 4 + C++ GDExtension

| 维度 | 评价 |
|------|------|
| 2D 渲染 | ★★★★★ 内建 TileMap、Sprite2D、AnimationPlayer，调色板支持完善 |
| 跨平台 | ★★★★☆ Windows/Linux/macOS/Web 原生支持；Switch 需社区 exporter |
| 核心逻辑分离 | ★★★☆☆ GDExtension 允许 C++ 编写逻辑，但与引擎生命周期耦合 |
| 单元测试 | ★★☆☆☆ 核心逻辑需 mock 引擎接口，测试复杂度较高 |
| 学习曲线 | ★★★★☆ 编辑器直观，GDScript 易上手，GDExtension 文档完善 |
| Web 导出 | ★★★★☆ 原生 HTML5 导出，但 .wasm 体积较大 |
| 社区生态 | ★★★★★ 活跃社区，丰富插件，中文资源丰富 |

## 3. 选型决策

### 3.1 最终选型：SDL3 + C++20

**决策理由**：

1. **跨平台覆盖最完整**：SDL3 是唯一一个原生覆盖全部 5 个目标平台（含 Switch via devkitPro）的框架，无需依赖社区非官方端口
2. **核心逻辑零依赖**：战斗公式、状态机、经验计算等核心逻辑为纯 C++20，可直接 gtest 单元测试，无需 mock 任何引擎接口
3. **原作架构对齐**：原作 DLZ.exe 基于 DirectDraw/Win32 API 的 C 风格架构，SDL3 的 C API 风格与原作最为接近，迁移映射最直观
4. **逆向工程成果复用**：已反编译的 768 个 C 函数可直接作为 C++ 实现的参考蓝图，结构体布局、全局变量映射、函数签名均已完整记录
5. **Web 端性能最优**：SDL3 对 Emscripten/WebAssembly 有成熟支持，战棋游戏对帧率要求低（30fps 可接受），Web 端完全可行
6. **包体极致轻量**：SDL3 运行时 < 1MB，加上素材总体积可控在 50MB 以内

### 3.2 技术栈明细

| 层次 | 技术选型 | 版本 | 用途 |
|------|----------|------|------|
| 语言 | C++20 | MSVC 2022 / GCC 13 / Clang 17 | 全栈开发语言 |
| 平台抽象 | SDL3 | 3.2+ | 窗口/输入/渲染/音频/线程 |
| 图像加载 | SDL3_image | 3.2+ | PNG/BMP 素材加载 |
| 音频混音 | SDL3_mixer | 3.2+ | WAV 音效 + OGG/MP3 BGM |
| 视频播放 | libmpeg2 + 自定义 FLC | - | MPEG 过场 + FLC 动画 |
| 字体渲染 | SDL3_ttf 或 stb_truetype | - | 中文字体渲染（HZK16 兼容） |
| 构建系统 | CMake | 3.24+ | 跨平台构建 |
| 依赖管理 | CMake FetchContent + vcpkg | - | 第三方库管理 |
| 单元测试 | Google Test | 1.14+ | 核心逻辑测试 |
| 代码规范 | clang-format + clang-tidy | - | 格式化 + 静态分析 |
| CI/CD | GitHub Actions | - | 自动构建 + 测试 |
| 版本控制 | Git | - | 代码版本管理 |

### 3.3 关键依赖说明

| 依赖 | License | 静态链接 | Web 支持 | 说明 |
|------|---------|----------|----------|------|
| SDL3 | zlib | ✅ | ✅ | 核心平台层，zlib 许可无法律风险 |
| SDL3_image | zlib | ✅ | ✅ | PNG 加载（仅用于开发期素材预览） |
| SDL3_mixer | zlib | ✅ | ✅ | 音频混音 |

## 4. 可行性论证

### 4.1 技术可行性

| 技术点 | 可行性 | 依据 |
|--------|--------|------|
| SDL3 渲染等效 DirectDraw | ✅ 高 | SDL3 GPU API 支持 2D blit、调色板索引、精灵动画 |
| 8-bit 调色板图像还原 | ✅ 高 | SDL3 支持 SDL_PIXELINDEX8 格式 + 调色板设置 |
| ANM RLE 动画解码 | ✅ 高 | 已完整逆向 4 opcode + delta 编码，直接 C++ 实现 |
| DirectSound → SDL3 音频 | ✅ 高 | SDL3_mixer 多通道混音等效 DirectSound |
| MCI → SDL3 视频 | ✅ 高 | MPEG 用 libmpeg2 解码，FLC 自定义解码器 |
| Emscripten Web 导出 | ✅ 高 | SDL3 官方支持 Emscripten，大量 2D 游戏先例 |
| Switch 移植 | ✅ 中 | devkitPro + SDL3 Switch 端口已有成熟方案 |
| 640×480 整数倍缩放 | ✅ 高 | SDL3 渲染目标 + 纹理缩放 |

### 4.2 工期可行性

| 阶段 | 预估工期 | 人力 | 依据 |
|------|----------|------|------|
| Phase 0: 工程基建 | 2 周 | 1 人 | SDL3 脚手架 + CMake + CI |
| Phase 1: 战斗核心 | 6 周 | 1 人 | 45 个精修函数 + 768 个反编译参考 |
| Phase 2: 战略层 | 6 周 | 1 人 | 状态机 20+ 模式 + 城镇系统 |
| Phase 3: 剧情完善 | 4 周 | 1 人 | 对话/过场/音频集成 |
| Phase 4: 多端适配 | 4 周 | 1 人 | Web + Switch 适配 |
| **总计** | **22 周** | **1 人** | 约 5.5 个月 |

### 4.3 风险可行性

| 风险 | 缓解措施 |
|------|----------|
| SDL3 仍为预发布版 | 锁定 3.2 stable release；API 变动范围可控 |
| Web 端音频延迟 | SDL3_mixer 对 WebAudio 有优化；战棋游戏对延迟不敏感 |
| Switch 开发权限 | 需 Nintendo Switch 开发者资质；可作为 Phase 4+ 独立推进 |
| MPEG 解码 GPL 风险 | 可替换为 LGPL 的 ffmpeg 或自行实现简化 MPEG-1 解码器 |

## 5. 备选方案回退计划

若 SDL3 方案在实施过程中遇到不可克服的障碍：

| 触发条件 | 回退方案 |
|----------|----------|
| SDL3 API 不稳定导致频繁重构 | 回退至 SDL2（API 更稳定，社区更成熟） |
| Web 端性能不达标 | 回退至 Raylib（Web 导出更轻量） |
| Switch 移植遇到技术壁垒 | 回退至 Godot 4（有官方 Switch exporter） |
