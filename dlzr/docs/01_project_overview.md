## 1. 项目背景

### 1.1 原作概况

| 项目 | 内容 |
|------|------|
| 游戏名称 | 抗日之地雷战 (Landmine War) |
| 开发团队 | 西山居 (Xishanju / Kingsoft) |
| 发行时间 | 1998 年 |
| 游戏类型 | 回合制战棋策略游戏 |
| 技术平台 | Windows 95/98, MSVC 5.0 编译 |
| 渲染引擎 | DirectDraw (COM) |
| 音频系统 | DirectSound + MCI |
| 分辨率 | 640×480, 8-bit 调色板 |
| 关卡数量 | 47 场战斗, 19 个城镇 |
| 角色数量 | 40 名可识别角色, 90 种兵种 |
| Executable | DLZ.exe, 771 函数, ~2.7MB 反编译代码 |

### 1.2 原作历史价值

《抗日之地雷战》是国产战棋游戏的黄金时代代表作之一，由求伯君领衔的西山居团队开发。游戏以抗日战争为背景，采用经典的回合制战棋玩法，融合了兵种克制、地雷布设、城镇经营等独创系统。其数值体系设计精巧，AI 行为逻辑严密，是研究早期国产游戏工程的珍贵样本。

### 1.3 复刻动机

- **文化遗产保护**：原作仅支持 Windows 95/98/XP，在现代系统上运行需兼容层模拟，体验严重退化
- **技术文档化**：通过逆向工程已完整解析原作全部 771 个函数、17 种 DAT 文件格式、完整数值体系，具备 1:1 复刻的知识基础
- **跨平台需求**：原作受限于 Win32 平台，复刻版可实现 Windows/Linux/macOS/Web/Switch 多端运行
- **工程现代化**：消除原始代码中的全局状态耦合、手动内存管理、平台 API 硬编码等技术债务

## 2. 项目目标

### 2.1 核心目标

| 编号 | 目标 | 验收标准 |
|------|------|----------|
| G1 | 玩法 100% 还原 | 所有角色属性、战斗公式、关卡数据、AI 行为、触发事件、胜负规则与原作逐字节一致 |
| G2 | 底层现代化 | 渲染/音频/输入/平台层全部替换为跨平台方案，消除 DirectDraw/Win32/MCI 依赖 |
| G3 | 五端覆盖 | Windows、Linux、macOS、HTML(Web)、Nintendo Switch 五平台可编译运行 |
| G4 | 工程规范化 | 模块化架构、单元测试覆盖核心逻辑、自动化 CI/CD 构建流水线 |

### 2.2 非目标（明确排除）

- **不修改玩法**：不做任何平衡性调整、难度曲线修改、新增游戏内容
- **不替换美术**：使用原作提取的全部素材（1030+ PNG 帧、152 WAV、33 MPG 过场），仅做分辨率适配
- **不重写引擎底层**：使用成熟游戏引擎/框架，不从零实现渲染管线

### 4.2 数据资产

> **数据策略 / Data Policy**
>
> 运行时 **直接读取原始二进制数据文件**（PEOPLE.DAT、FIGHT.DAT、GAME.DAT 等），
> 不依赖任何中间转换格式（JSON/CSV 等）。中间格式仅用于逆向工程研究阶段的数据分析，
> **不随重制版发布，不嵌入运行时**。存档系统直接读写原作二进制存档格式。
>
> Runtime reads original binary data files directly. No intermediate formats
> (JSON/CSV) are distributed, embedded, or required at runtime.
> Save system reads/writes the original binary save format.

## 6. 验收标准总则

### 6.1 玩法一致性验证

- **数值验证**：所有计算公式（攻防、经验、技能伤害）通过单元测试，输入输出与原作反编译代码逐一对齐
- **行为验证**：AI 行为序列与原作 FIGHT.DAT 行为脚本对比，无偏差
- **视觉验证**：战斗画面截图与原作截图逐像素对比（允许抗锯齿差异）
- **流程验证**：47 关通关流程完整可走通，所有触发事件正确触发

### 6.2 工程质量标准

- **代码覆盖**：核心逻辑层（战斗公式、状态机、经验计算）单元测试覆盖率 ≥ 90%
- **构建稳定**：CI 流水线每次提交自动构建，零 warning 编译通过
- **文档完整**：所有模块有 API 文档，关键设计决策有 ADR 记录
- **无内存泄漏**：Valgrind / AddressSanitizer 零泄漏报告

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 部分函数逻辑未完全逆向 | 某些 AI 行为细节可能遗漏 | 保留 Ghidra 数据库，随时可回溯查证 |
| Web 端性能不足 | Emscripten 编译后帧率不达标 | SDL3 对 WebGL2 有成熟优化；战棋游戏对帧率要求低 |
| Switch 适配复杂度 | 需要 devkitPro 工具链 | 架构预留 HAL 层，Phase 4 后独立适配 |
| 原作素材版权 | 复刻版使用原作素材的法律风险 | 项目定位为个人研究/学习用途，不商业化分发 |
| 单人开发周期长 | 22 周计划可能延期 | 核心逻辑优先，表现层可迭代；模块化设计支持并行开发 |
